# 채널별 브랜드 컨텍스트 고도화 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Supabase `channels` 테이블의 `ai_system_prompt`와 `description` 필드를 5개 채널별로 완전히 재작성하여 채널 고유의 씬 감도와 카피 톤을 확보한다.

**Architecture:** 애플리케이션 코드 변경 없음. `buildAiPrompt()`는 이미 `ch.ai_system_prompt`를 직접 사용하므로 Supabase DB 데이터만 업데이트하면 즉시 반영된다. SQL 파일을 로컬에 저장 후 Supabase SQL Editor에서 실행하는 방식으로 진행한다.

**Tech Stack:** PostgreSQL (Supabase), SQL dollar-quoting ($$...$$)으로 멀티라인 문자열 처리

짧고 밀도 있게. 설명하지 말고 보여줄 것. 설계 의도를 읽되, 그 공간에 서 있는 사람의 감각으로 번역할 것. 형용사를 아낄수록 강해진다.

### Task 2: Supabase SQL Editor에서 실행

**Files:**

- [ ] **Step 1: 채널 이름 사전 확인**

Supabase → SQL Editor에서 아래를 먼저 실행하여 채널 이름이 정확히 일치하는지 확인:

```sql
SELECT name FROM channels ORDER BY created_at;
```

예상 결과:
```
spacelog
CAPITALFLOW
obscurelife.kr
Nightcall.audio
mma_seoul
```

이름이 다르면 `supabase-channel-prompts.sql`의 `WHERE name = '...'` 값을 실제 이름으로 수정한다.

- [ ] **Step 2: SQL 실행**

`supabase-channel-prompts.sql` 파일의 전체 내용을 복사 → Supabase SQL Editor에 붙여넣기 → Run.

예상 결과: 각 UPDATE마다 `1 row affected` 메시지, 마지막 SELECT에서 5개 채널의 `prompt_preview`가 채워진 상태로 출력됨.

- [ ] **Step 3: 결과 확인**

마지막 SELECT 결과에서 아래를 확인:
- `description` 컬럼: 각 채널별로 다른 1-2문장이 채워져 있음
- `prompt_preview` 컬럼: `[채널 정체성]`으로 시작하는 텍스트가 표시됨
- 5개 채널 모두 `NULL`이 없음
